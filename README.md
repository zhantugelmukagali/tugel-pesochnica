# TUGEL · 3D Sandbox

Интерактивная инженерная песочница для исследования модульного робота TUGEL. Она помогает сравнивать конструкции, проверять геометрию движений и находить ограничения до изготовления физических модулей.

Приложение работает в браузере. Исходники — JavaScript, Three.js и Vite; серверная часть, аккаунт и API-ключи для запуска не требуются.

## Режимы

### Шарнирная цепь

Первый модуль закреплён, остальные связаны управляемыми шарнирами. Доступны две схемы осей:

- **Плоская:** все шарниры вращаются вокруг вертикальной оси.
- **Пространственная:** чередуются локальные оси поворота Y и Z.

Модель рассчитывает положения и ориентации корпусов, проверяет их пересечения с помощью ориентированных ограничивающих параллелепипедов (OBB), пересечения с плоскостью пола и ограничения углов. Переходы проверяются по промежуточным положениям, а не только по конечной форме.

Для каждого шарнира оценивается **статический момент силы тяжести вокруг его управляемой оси** от расположенных дальше по цепи модулей. Это не полный расчёт привода: не моделируются трение, разгон, люфты, деформации, ударные нагрузки и распределение опорных реакций. У вертикального шарнира гравитационный момент вокруг оси может быть нулевым, хотя реальные двигатели всё равно преодолевают трение и инерцию.

### Отдельные модули

Кубические модули перемещаются по плоскости в заданную конфигурацию. Планировщик использует дискретную решётку, поиск A* и последовательное движение через промежуточные позиции, учитывая занятое другими модулями пространство.

Это модель **идеального всенаправленного перемещения**. Она не воспроизводит колёсную кинематику, сцепление с поверхностью или механическую стыковку. Расположение модулей в форме не означает, что между ними появился физический замок.

## Управление

- Вращайте сцену мышью или касанием; приближайте и отдаляйте камеру.
- Выбирайте модуль в сцене, чтобы исследовать его состояние.
- Изменяйте параметры конструкции и сравнивайте формы.
- Запускайте движение, ставьте его на паузу и возвращайте систему в исходное состояние.

Текстовые команды в этой версии обрабатываются детерминированными правилами. LLM/LMM не подключена; приложение не выдаёт выбор заранее известных действий за работу обученной модели.

## Сохранение экспериментов

- **Сохранить** записывает одну конфигурацию в `localStorage` текущего браузера; новая запись заменяет предыдущую. Для восстановления есть отдельная кнопка загрузки.
- **Экспорт** скачивает JSON формата `tugel-lab`, версия 1. Импорт проверяет тип сцены, диапазоны параметров, число и допустимость углов; для исходного положения цепи также проверяются пересечения.
- В режиме цепи сохраняются текущие и целевые углы. В режиме отдельных модулей сохраняются параметры и выбранная форма; после загрузки маршрут строится заново от начальных позиций. Текущий шаг маршрута и ход анимации не сохраняются.
- Кнопка снимка скачивает PNG с 3D-сценой.

Сохранение локальное: данные не отправляются в облачную базу и не синхронизируются между устройствами. Для переноса используйте JSON. Если браузер запрещает `localStorage`, экспорт остаётся доступен.

## Запуск

Требуется Node.js 22.12+ или актуальная совместимая версия Node.js 24.

```bash
git clone https://github.com/zhantugelmukagali/tugel-pesochnica.git
cd tugel-pesochnica
npm ci
npm run dev
```

Откройте адрес, который выведет Vite. Для рендеринга нужен браузер с поддержкой WebGL2.

Проверки и сборка:

```bash
npm test
npm run build
```

Статическая сборка находится в `dist/`. Её можно разместить на хостинге статических сайтов. Для сервиса Sites конфигурация размещения хранится в `.openai/hosting.json`.

## Структура проекта

```text
src/
  main.js            интерфейс и состояние приложения
  scene.js           3D-сцена, камера и выбор модулей
  kinematics.js      кинематика цепи и геометрические проверки
  swarm.js           маршруты отдельных модулей
tests/               автоматические проверки моделей
.github/workflows/   проверка тестов и сборки в GitHub Actions
```

## Как использовать результаты

Песочница проверяет выбранные математические модели. Успешная виртуальная трансформация не доказывает, что физический прототип сможет её выполнить. Для перехода к железу потребуются испытания шарниров, питания, креплений, соединителей и приводов под реальной нагрузкой.

Практический следующий этап — сопоставить измерения стенда из нескольких модулей с параметрами песочницы и уточнять модель по данным экспериментов.
